# rngseed: durable seed transactions and entropy boundary

`rngseed save FILE` waits for initialized kernel randomness, obtains 512 bytes
with blocking `getrandom`, and writes a caller-owned 0600 file. `rngseed load
FILE` accepts a caller-owned, single-link regular file of 32–4096 bytes with
exactly mode 0600. A missing basename is first boot and succeeds with a diagnostic;
a missing parent directory is an error. Parent directories must be trusted and
private. This is a privileged boot service interface, not an untrusted seed
import interface.

Both operations open and exclusively lock the parent directory without waiting
for another rngseed operation. All file operations then use that directory FD.
A contended lock fails; callers may retry. Directory locks serialize cooperating
rngseed calls, including multiple paths in the same directory. They do not
protect against arbitrary writers, filesystem snapshots, cloned machines, or
restoring an old seed from backup.

Writes create a unique exclusive temporary file with mode 0600, enforce that
mode, completely write the bytes (retrying EINTR and short writes), sync the file,
close it, rename it over FILE, then sync the directory. Any write, close, rename,
or sync failure is reported. A failure before rename retains an existing save
file; a directory-sync failure after rename can leave the new file installed.
Zero-progress write/getrandom results fail with EIO rather than looping forever.
Temporary files and open FDs are cleaned on error. Seed buffers are explicitly
wiped through volatile stores.

Load constructs `RNDADDENTROPY` with the complete original bytes, the exact buffer
size and an entropy count capped by the positive kernel pool size when available.
It unlinks FILE and syncs that removal **before** opening the random device and
requesting credit. This ordering prevents a crash, failed getrandom, or failed
replacement from leaving the credited seed available at FILE. Successful credit
is followed only by nonblocking getrandom. EAGAIN is a consumed seed with success
and a diagnostic; other refresh failures return failure. A second load then sees
first boot. If credit/device-open fails, load attempts to restore the identical
uncredited bytes through the complete write/sync/rename protocol and reports any
restoration error. A failure to sync consumption prevents credit entirely.

Raw seeds have no header, checksum or authentication. Truncation below 32 bytes,
oversize, unsuitable file types, permissions and links are rejected. Arbitrary
changes to a size-valid private seed cannot be distinguished from random bytes;
0600 does not establish entropy provenance. Only use seeds generated by this
service from an initialized CRNG. Replacing the format with an authenticated
provenance scheme would require separate compatibility and key-management work.

## Safe validation

`tests/rngseed-host.c` retains the original save/freshness/first-boot/invalid-input
checks and now always intercepts credit as EPERM, even as root.
`tests/sol-rngseed-host.c` links the real production source with linker wrappers.
Its ioctl wrapper has no call to real ioctl: successful credit is an injected
boundary, and no test credits the host. It verifies exact request bytes, lengths,
credit caps, flags, transaction order, EINTR/short reads and writes, zero progress,
size bounds, permissions/types/links, failed credit restoration, failures before
and after consumption, replacement failures, repeat calls, contention, diagnostic
output failure, temporary-file cleanup and FD counts. ASan/UBSan covers both host
harnesses. `tests/sol-rngseed-check.sh` checks the built native shell with empty
PATH and repeated calls, and invokes load only on a missing file.

Builds and measurements must use the campaign resource gates. Build the focused
harnesses with `tests/sol-rngseed-build.sh OUTPUT_DIR`. The harnesses compile
against the configured `build/bash-5.3` tree; registered checks run those
harnesses, not `out/bash-sol-rngseed`.
Neither correctness execution nor
`bench/sol-rngseed.py` compiles anything. rngseed requires no helper or companion
loadables (the resolver includes its default _jsmn helper) according to `config/helpers.json` and the resolved build selection.
The existing global test registration remains usable; integration should add the
focused harness/check script without changing its historical assertions.

## Measurement method

`bench/sol-rngseed.py --harness OUTPUT_DIR/rngseed-host --output REPORT.json`
measures 100 validated save transactions and 100 validated load transactions per
sample, with deterministic getrandom and intercepted entropy credit. It checks
every resulting byte against an independently specified byte formula, exact
length/mode, return status, credit boundary and temporary-file cleanup. It also
separately measures 100,000 512-byte deterministic fills and 100,000 complete
512-byte host getrandom fills. The latter checks API return counts, not entropy
quality. Production has no userspace cryptography; getrandom is its random-source
cost. The two fill cases separate that cost from the filesystem and shim work.

Each case has a warm-up and nine samples on one recorded CPU. Per-call monotonic
times exclude fixture reset and validation, while batch wall times include them
and process startup. Raw reports retain all samples, statuses, binary/source
SHA-256, compiler/runtime versions, CPU affinity, fixture hashes and reset rules.
Transaction timings include trace bookkeeping and poolsize/credit shims. These
are syscall-shim/API measurements with no BusyBox/systemd ratio: their credit
policies and persistent seed formats are not equivalent workloads. Host cached
filesystem sync times do not establish board storage durability or boot latency.
New evidence belongs in the task evidence directory, preserving historical data.

## True kernel and board qualification

These tests establish the software transaction scope. They do not establish
entropy quality or actual kernel credit effectiveness. Those require a disposable
VM or isolated board with its own random pool and storage, never the host pool:

1. Boot with an uninitialized CRNG, no trusted inherited seed, and no alternate
   entropy source that would mask the observation. Record kernel/configuration,
   capabilities, random-driver policy and pool size. Confirm nonblocking
   getrandom returns EAGAIN before credit.
2. Establish the first-boot behavior and save a seed only after blocking
   getrandom succeeds. Preserve the private seed across a cold boot, avoiding
   VM snapshots/clones or another boot service consuming it.
3. In the isolated environment, load once with the required CAP_SYS_ADMIN and
   verify real RNDADDENTROPY acceptance, then nonblocking getrandom readiness,
   exact seed refresh and absence of re-credit on repeat/error paths. Measure
   boot CRNG readiness separately from file transaction latency. Verify
   capability denial and restoration separately.
4. Cut power or inject filesystem crash/recovery at consumption sync, credit,
   file sync, rename and directory sync. A recovered FILE must contain an
   uncredited original or a fully written fresh seed, or be absent. Test the
   actual board filesystem and storage flush guarantees. A crash after durable
   consumption may lose a seed and require entropy acquisition on the next boot.

Statistical byte tests, a successful shim ioctl, a fast getrandom on an already
initialized host, or a root UID alone cannot qualify kernel entropy credit.
