# nano: second pass — input framing, display safety, signals, fast highlighting

This pass started from the justify, spell, completion and selection work in
`docs/opus-nano.md`. It checked that work again through new PTY and GNU nano
oracles and found nothing to correct. It also fixed five defects that affect
real use. It removed the per-keystroke full reparse of highlighted files,
and it bounded what a key costs in a large highlighted script to a 25 ms
reparse budget, with the rest finished while input is idle.

```sh
./build.sh --include nano,ts --name nano          # ts is a required companion
out/bash-nano -c 'PATH=; nano notes.txt'
```

## What changed

### Keys arriving in a burst are no longer lost

The key reader read everything that followed an ESC byte, until a 100 ms
gap or a full buffer, as one key. Arrow keys, Alt keys and text that came in
the same write were swallowed. For example, `→ → a b ← c` pasted or typed
over a slow link left the file unchanged; GNU nano gives `01acb…`. Key
auto-repeat over ssh coalesces the same way.

Each read now frames exactly one key:

- **CSI:** `ESC [`, parameter bytes, then a final byte from 0x40.
- **SS3:** `ESC O`, then one byte.
- **Alt:** ESC followed by one character, including a UTF-8 one.
- **ESC ESC:** returns the first ESC and keeps the second.
- **UTF-8:** a character of the length its lead byte declares.

A byte that cannot continue the key is pushed back and starts the next one.
It is no longer dropped (as `0xc3` followed by `A` used to drop the `A`). A
CSI too long for a prompt's buffer is consumed whole and truncated.

SS3 cursor keys (`ESC O A`, sent in application cursor mode) work like
their CSI forms. `ESC [ 1 ~`/`ESC [ 7 ~` mean Home and `ESC [ 4 ~`/`ESC [ 8 ~`
mean End.

### Up and down keep the screen column

Vertical movement used to keep the *byte* offset, so on lines with wide
characters, tabs or multibyte text the cursor jumped columns. It now works
as GNU nano does:

- The first ↑/↓/^P/^N/PgUp/PgDn remembers the cursor's screen column, and
  any other key forgets it, so passing through a short line returns to the
  same column.
- The cursor lands after the last cluster that ends at or before that
  column. It never lands inside a wide character or a tab.

### Files cannot send escape sequences to the terminal

The body, the title line and the status line used to write text raw:

- A leading tab was not drawn at all, and other tabs reached the terminal
  as raw tabs, so the cursor and the text disagreed.
- Control bytes reached the terminal. A file or file name containing
  `ESC ] 0 ; … BEL` set the window title, and `ESC [ 2 J` cleared the
  screen. Words from the spell helper and typed prompts reached the
  status line the same way.

Everything is now drawn in display form, as in GNU nano:

| text | shown as | columns |
|---|---|---|
| tab | spaces to the next multiple of 8 | 1–8 |
| C0 control, DEL | `^@` … `^_`, `^?` | 2 |
| C1 control U+0080–U+009F | `` ^` `` … `^~`, `^=` for U+009F | 2 |
| malformed UTF-8 | U+FFFD, once per bad sequence | 1 |

Cursor placement, horizontal scrolling, soft wrap and vertical movement use
the same widths, so the cursor sits where the text is drawn. A tab, wide
character or caret form cut by the left edge shows its visible columns as
blanks.

The title and status lines are cut to the terminal width. A long message
such as ^G help on 80 columns used to wrap on the bottom row and scroll the
whole frame.

### SIGHUP and SIGTERM restore the terminal and rescue the buffer

A termination signal used to kill the shell with the terminal still raw and
on the alternate screen, and a modified buffer was lost. Closing the
terminal window does this too. Now, as in GNU nano:

1. The session ends: the main loop, a prompt or a running spell helper
   stops. The helper is killed and reaped.
2. A modified buffer is written to `FILE.save`, or `FILE.save.1`, `.2`, …
   when that exists (`nano.save` without a name). The file is created with
   `O_CREAT|O_EXCL|O_NOFOLLOW`, mode 0600, so it never replaces a file or
   follows a symlink. `nano: buffer written to NAME` (or why not) goes to
   stderr.
3. The alternate screen is left and termios restored.
4. The shell's own handler is put back and the signal raised again. A
   `trap` runs (the builtin returns 128+signal), or the default action
   ends the shell. A signal the shell ignores (`trap '' TERM`, nohup)
   stays ignored, and the editor keeps running.

SIGINT, SIGQUIT and SIGTSTP are not generated by the keyboard (raw mode clears
ISIG, and ^Z is undo); signals sent by other processes keep their previous
behaviour.

### Highlighted files are no longer reparsed on every key

Every edit cleared the highlight cache, and the next frame reparsed and
recoloured the whole buffer with tree-sitter. That costs about 0.55 s per MiB
to parse plus 0.4 s per MiB to resolve captures, on every key. A new
`bashts_sgr_range` in the ts companion keeps the parse tree and a copy of
its source between calls. It works out the changed span by comparing the
text with that copy, so typing, bursts, undo and redo all become one
`ts_tree_edit` plus an incremental reparse. Captures are then resolved only
for matches intersecting the requested byte range, with the same precedence
rules.

nano asks for the lines that can be drawn plus one screen above and below,
and reuses that window on cursor-only repaints. The tree lives for the
session, so memory use stays at the size of one parse, which the old code
also built on every frame.

`nano selftest-highlight` is the oracle. After each of 160 random edits,
undos and redos in bash, JSON and Markdown text, it compares every coloured
window with a from-scratch full parse (`bashts_compute_sgr_map`), byte for
byte. It also checks that the comparison is not vacuous: coloured bytes,
partial windows, and frames where the previous text's colours differ.

### Large highlighted files stay responsive

Incremental reparsing alone did not make large shell scripts usable. After
an edit in the middle of a 1 MiB script, each key still cost about 197 ms,
and 1.4 s at 8 MiB. Timing each phase of `bashts_sgr_range` in a probe build
showed where it went:

| phase, 1 MiB script, per key | ms |
|---|--:|
| find the changed span, edit the tree | 0.4 |
| incremental reparse | 136–167 |
| free the old tree | 21–29 |
| colour the window (query) | 4–6 |
| first, full parse (for comparison) | 365 |

tree-sitter's parser log explains the reparse cost. tree-sitter-bash marks
every top-level statement *fragile*, because the reduction that builds it
comes from a grammar conflict. A fragile node cannot be reused, so after an
edit everything up to the end of the file is lexed and reduced again. Every
simple form behaves this way (`echo x`, a pipeline, `&&`, a trailing
comment). A script built mostly from functions and blocks (`build.sh`
repeated to 64 KiB) still reparses in a quarter of the full-parse time. This
is a property of the grammar, not of how nano calls the parser.

The parser can stop at a deadline and resume later, so each frame now gets
a 25 ms budget:

- `bashts_sgr_range_budget` (ts companion) runs the reparse until the
  deadline. If the deadline passes, it keeps the parse halted and colours
  the window from the old tree with the edit applied to its positions.
  Unchanged text keeps its colour, and typed text is uncoloured or takes
  the colour of the node it lands in.
- While no key is waiting, nano's main loop resumes the parse in 10 ms
  slices through `bashts_sgr_continue`. When it finishes, nano redraws with
  the settled colours, which equal a full parse.
- A key that changes the text abandons the halted parse and edits the tree
  again, so typing never waits for a parse that the next key would make
  stale.
- Opening a large script shows the text at once and colours it when the
  first parse finishes. Before, the first frame waited for that parse
  (0.4 s per MiB).

Small files are unaffected: their reparse fits in the budget, and every
frame is coloured exactly as before. Only a buffer whose reparse exceeds
25 ms shows the edited-old-tree colours for the time the reparse takes.
While keys keep arriving faster than that, its colours stay approximate,
and they settle at the first pause. `bashts_sgr_range` keeps its meaning,
with no budget. Nothing else calls the new functions.

The halted parse runs on a private copy of the text, so later edits to the
buffer cannot reach it. A parse that fails outright, rather than halting at
the deadline, releases the state, and the text is drawn uncoloured; the
idle loop cannot spin on it.

### Smaller fixes

- The highlight language is reset at the start of each call. A `nano` with
  no file, after editing a `.sh` file in the same shell, no longer
  highlights as bash.
- The `--speller` help text was garbled by an earlier insertion; it now
  reads in order.
- The PTY check of SIGTERM during a hung spell helper now kills the helper
  if it is still alive. An earlier run against the unchanged starting
  binary, where that check fails, had left one running.

## Intentional difference from GNU nano: no added final newline

By default GNU nano keeps an empty "magic line" at the end of the buffer, so
a saved file always ends with a newline. This builtin saves exactly the
typed text, which is GNU nano's `-L`/`--nonewlines` behaviour. The burst and
movement oracles therefore run GNU nano with `-L`. Without it, they differ
only after keys that reach the last line: a right-arrow there moves GNU onto
its magic line.

## Second check of the inherited work

New PTY checks drive the predecessor's features through the real terminal
path:

- **Justify:** `M-J` at four width settings (`--fill=30`, `-r 45 -M`,
  `--fill=-20` at 60 columns, `-r 0` at 50) equals GNU nano 8.4 byte for
  byte. One `^Z` restores the text, `M-E` re-applies it, and repeated `^J`
  walks the paragraphs.
- **Spell:** prompt editing with Backspace, whole-word replacement as one
  undo step, skip, Esc cancel with the buffer left unmodified, a failing
  helper whose stderr stays off the screen, and SIGTERM during a hung
  helper (stopped in well under a second; only that helper is killed).
- **Completion:** a UTF-8 fragment (`ü`) cycles `über`, `übel`, `üppig`,
  back to the fragment and round again, and ^Z steps back.
- **Selection:** the mark follows its text through an edit before it, undo
  and redo; `M-^` copies exactly the marked clusters.
- **Restoration:** termios is identical before, between and after two
  calls, and each call enters and leaves the alternate screen once.

Run against the unchanged starting binary, the justify, completion,
selection and restore groups and the first three spell checks pass. The
SIGTERM-during-a-hung-helper check fails there, because that behaviour is
new. These checks confirm the inherited behaviour and found no defect in it.
The burst, movement, display and signal groups fail on the starting binary,
each at the defect described above (logs `base-sol-pty-*.log`).
