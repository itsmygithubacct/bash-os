# diff: focused validation and measurement

The supported interface is normal diff output and `-u`, `-q`, and `-i`, including
combined short flags, `--`, and stdin operands. Status is 0 for equal inputs, 1
for differences, and 2 for errors. Unified headers intentionally contain only
filenames, without GNU's filesystem timestamps. This is a file comparison
builtin; GNU's directory comparison and other options are outside this scope.

`tests/diff-safety.py` checks GNU output and status for identical files, sparse
changes, all-changed files, long records, case folding, binary data, NULs around
the binary-probe and output-buffer boundaries, and missing final newlines.
It also covers both stdin operand positions and `diff - -`, output ordering,
long filenames, `/dev/full`, invalid inputs, descriptor recovery under a low FD
limit, and recovery after exhausting the native address-space limit. Existing
edit-address and context assertions remain. For repeated records, 120 seeded
cases apply the emitted normal scripts and independently check minimal edit
counts against an LCS oracle; these cases allow alternative minimal alignments.
GNU comparisons run in `LC_ALL=C`; this does not claim GNU's full option set or
multibyte case-folding behavior.

`diff - -` now returns without reading stdin, matching GNU and leaving input
available for a later shell `read`. The regression checks subsequent input in
all supported comparison modes and checks a closed stdin descriptor. The
previous implementation consumed stdin into a shared buffer before returning.

`tests/sol-diff-alloc.c` includes the production source with allocation hooks.
`tests/sol-diff-alloc.py` fails each allocation in turn, checks error status,
asserts no production allocations remain, and compares files again in the same
shell. This also covers buffer growth, line-array growth, and edit-trace rows.
The build script produces native and ASan/UBSan modules; tests run separately
without compiling. ASan runs skip the address-space-limit case because ASan
reserves a large virtual range; the native run must cover that case.

Build only the command with `./build.sh --include diff --name sol-diff --no-strip`.
No companion loadable is required. The selection infrastructure stages its
default `_jsmn` helper. No shared helper source is changed.

After that build, compile fixtures with
`bash tests/sol-diff-build.sh ARTIFACT_DIR out/bash-sol-diff`, then run:

```sh
python3 tests/diff-safety.py out/bash-sol-diff
bash tests/diff-check.sh out/bash-sol-diff
python3 tests/sol-diff-alloc.py ARTIFACT_DIR/bash-native
BASHOS_TEST_SANITIZED=1 python3 tests/diff-safety.py ARTIFACT_DIR/bash-sanitize
python3 tests/sol-diff-alloc.py ARTIFACT_DIR/bash-sanitize
```

All compilation must use the campaign build gate, and measurement must use its
bench gate. `bench/sol-diff.py` never builds. It accepts `--binary LABEL=PATH`
repeatedly for interleaved comparisons, `--source-for LABEL=SOURCE` for source
provenance, `--profile` for syscall summaries, and
`--profile-fixture LABEL=MODULE` for untimed allocation/copy/comparison counters.

The historical fixture is regenerated exactly: seed 20260908, 12,000 generated
records truncated to 423,000 bytes, 24 identical-file comparisons per sample.
Additional fixtures measure real sparse scripts in normal and unified modes,
quiet comparison, 1 MiB lines, case-equivalent inputs, empty-sided output, and
all-changed inputs at 250, 500, 1,000, and 2,000 lines per side. Each case has one
warm-up and seven samples, alternating implementation order on one recorded CPU.
Every invocation's status and every output byte are checked, including warm-up;
NUL-framed pass boundaries also detect missing or doubled later outputs. Only
the documented unified-header timestamps are normalized. Files remain
unchanged throughout a case. The JSON `lines` fields count newline delimiters;
the truncated historical fixture can also contain a partial final record. Byte
counts and hashes define the exact inputs. Timings include shell startup, a shell loop, and
output to a private regular file. Memory scaling uses the shell's own Linux
`/proc/PID/status` VmHWM, read with shell builtins at the end of each batch.
That measures builtin allocations but excludes GNU diff's child process, so
there is no GNU memory ratio. Diagnostic `wait4` RSS values are also retained;
they can inherit a high-water floor from the spawning Python process and must
not substitute for VmHWM. The initial baseline report used only `wait4`; its
small-input memory values are superseded by the paired report. Reports record
fixture, source, binary, and instrumentation hashes,
tool versions, raw sample distributions, affinity, and host load.

The benchmark refuses to overwrite an existing report. Historical reports and
shared catalog files are not regenerated by this work.

The implementation now keeps length-bearing views into the loaded buffers,
finds record endings with `memchr`, and saves only the `d+1` reachable frontier
cells at edit depth `d`. Normal and unified output use the existing 64 KiB
per-invocation output helper, including its terminal flushing and write-error
handling. The shared helper is unchanged. Quiet comparisons require no edit
script, and an empty-sided comparison constructs its known script directly.

For nonempty inputs, normal and unified comparison still have Myers' quadratic
worst case. With `L = n+m` input lines and edit distance `D`, the live arrays
are O(L) and saved trace cells are O(D²), in addition to the loaded bytes and
line views. The old trace saved O(LD) cells. When no lines match, `D = L`, so
both time and saved trace memory remain quadratic. The time bound is at line
level: comparing long candidate records also costs the bytes examined. Inputs
are fully loaded rather than streamed. Native memory-limit recovery remains a
required test; exhaustion is reported as status 2 before output generation.

The native executable and native allocation fixture each passed all eleven safety
test methods, and the existing smoke script passed eight checks. ASan/UBSan
passed ten applicable safety methods with only the documented address-space
case skipped. Allocation injection passed 281 failure/recovery and endpoint
checks in each of the native and sanitized fixtures; every invocation left zero
live production allocations. These runs use an empty PATH for builtin calls.

Matched final measurements used Intel(R) Core(TM) i7-9850H CPU @ 2.60GHz, pinned to CPU 11. GNU bash, version 5.3.15(1)-release (x86_64-pc-linux-gnu); diff (GNU diffutils) 3.10. Both builtin builds use the same compiler and production flags recorded in the build logs. The raw reports, distributions and hashes are retained with the task receipt.

The 2,000-line all-changed profile recorded 4,003 writes before and 2 after, including the harness's pass marker. The unchanged shared buffer emits at most 64 KiB per write; the long-line case is included above rather than assuming all record sizes benefit equally.

For the sparse normal script, untimed hooks recorded 24,040 allocation requests before and 40 after, and 1,967,989 versus 177 source-level memcpy bytes. These counters cover the production source and included output helper, not libc's internal allocations or copies. The memcmp byte field records requested lengths, not the bytes actually examined. Instrumented modules supply counters only; all timings use production executables.

The all-changed normal-output rows retain the adversarial workload and show the remaining quadratic limit. Quiet and empty-sided fast paths are separate cases; their timings do not substitute for edit-script generation.
